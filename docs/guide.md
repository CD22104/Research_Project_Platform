# 使用说明

## 在哪里做什么

| 地方 | 用来做什么 |
|---|---|
| 这个控制台（Mac 上 http://localhost:8765/ ） | 看今天要你决定什么、什么卡住了；看各项目的研究（方法、实验、结果）和工作（任务、决定、会话）；回复待办、采纳决定、确认结论；看显卡和会话 |
| 手机 Claude App 或 claude.ai/code | 和项目会话说话：在项目的文件夹（常驻入口）里开对话，讨论方向；做一张任务卡也在这个文件夹里新开一个对话，说「做 <任务 id>」。后台开的任务会话叫「<项目>·<任务>」，在「No folder」里 |
| a100 上的「研究服务台」会话 | 服务器、账号、密钥、ssh、控制台本身；运行下面带 `!` 的命令 |
| 其他服务器上的 Claude 会话 | 只在需要时用，例如某个任务只能在那台机器上操作 |

## 一个项目怎么推进

| 步骤 | 你做的 | 会话和程序做的 |
|---|---|---|
| 1. 新建 | 在 a100 会话里说 `新建项目 <名字>`，确认它列出的设定，运行它给的两行命令 | 建目录、记录骨架、实验设置、方法步骤 |
| 2. 定方案 | 在 App 里点项目名，和项目会话讨论 | 写方案；你拍板的事记成「候选决定」，挂到控制台 |
| 3. 采纳决定 | 控制台「讨论与决定」或「今天」里点「采纳」 | 采纳的决定写进每个新会话开场读到的事实包，不会被忘掉 |
| 4. 拆任务 | 看一眼「任务」看板，有意见就说；在项目文件夹里新开对话说「做 <任务 id>」（任务卡上可以复制这句话） | 项目会话把这一轮拆成任务卡；一张卡一个对话，开场先检查能不能开工、改代码的卡进自己的 worktree |
| 5. 要用卡 | 在待办里批准用卡、写预期（猜不到就选一个选项） | 任务会话用 boardrun 启动训练，卡改成「等运行」，会话结束，不占 token |
| 6. 训练期间 | 想看进度就看控制台 | 训练每分钟写心跳；收尾程序每 5 分钟检查，停掉的标「被中断」 |
| 7. 出结果 | 在实验的「一页纸」上看结果和你的预期对照，给结论 | 卡变「可以继续」，分析会话写一页纸和报告，请你确认结论 |
| 8. 下一轮 | 回到第 2 步 | 项目会话对话太长时（会话页标黄），开一个新的，说「接着来」 |
| 9. 结束 | 在项目会话里说 `结束项目` | 起草结论、释放显卡、问 checkpoint、提交、归档、关入口 |

## 控制台里看什么

- **今天**：等你决定的事（一条一行，点进去回复）、卡住的事（运行状态存疑、任务等人、回复没处理）、正在推进的项目和你上次来之后的变化。
- **项目页顶部**：现在要回答的问题、有效的决定、下一步、最新证据。
- **研究**：概况（上次来之后的变化、等你的、正在进行的、最近的一页纸）、方法、实验（分支图，每个实验最上面是「一页纸」）、运行（一张表：运行之间不同的设置和指标，点表头排序，点设置值只看这些；可以切到交叉表，比如条件 × 策略 × 模型，格子是某个指标；排序和筛选都在网址里，可以直接发链接）、样例、实验设置、文档（含会话画的「图解」，在隔离的框里显示，可以「在新窗口打开」）、论文（讨论方案时会话记下的论文清单，按属于哪一步分组；读完了打勾，会话下次开场就知道你读过哪些）。带虚下划线的词，鼠标放上去有解释。
- **工作**：任务（看板）、讨论与决定（候选决定可以直接采纳；讨论纪要）、会话、时间线、记录维护（格式问题，由会话修，不用你管）。
- **会话**：a100 上所有 Claude 会话：在工作还是空闲、挂在哪张任务卡上、上下文多大（开着的会话超过 15 万标黄，建议换新；已结束的整行灰色）、用了多少 token。只读这些数字，不读对话内容。

## 待办怎么回复

1. **回复**：每条有背景、选项（标「建议」的是会话推荐的）和补充说明框。选好、写好，点「提交回复」。
2. **两种处理方式**：
   - 不勾「直接处理」：这条显示「已回复 · 等会话处理」，等你在项目会话里说 `处理回复`。
   - 勾上「直接处理」：a100 的派活程序几分钟内起一个会话专门处理这条，处理完结果写回待办。
3. **进度**：会话开始处理时显示「会话已领取」；处理不下去显示「受阻」和原因，并另留一条待办问你。
4. **办完**：移到「最近 7 天办完」，写着你的回复和会话做了什么。

结论等你确认的实验、等你采纳的决定，也在待办里，用同样的方式回复。

## 新建项目

1. **起草**：在 a100 上的任意 Claude 会话里说 `新建项目 <名字>`（英文小写和连字符，例如 `jev-authz`）。
2. **确认**：在同一个会话里回复你的修改，没提到的视为同意。
3. **起常驻入口**：在 a100 会话的输入框里运行 `! ~/bin/rc-start <名字>`。
4. **回答信任提问**（每个项目只有第一次）：`! tmux send-keys -t '=rc-<名字>:' y Enter`
5. **开始用**：大约一分钟后，App 里会出现这个项目名，点它开会话；控制台左侧栏也会出现这个项目。

## 暂停、恢复、结束

| 想做什么 | 在哪 | 怎么做 |
|---|---|---|
| 暂停项目 | 项目会话 | 说 `暂停项目`。确认没有任务在跑后标为「暂停」，控制台移到「暂停」一栏 |
| 恢复项目 | 项目会话 | 说 `恢复项目`；入口关掉了的话先 `! ~/bin/rc-start <名字>` |
| 结束或放弃 | 项目会话 | 说 `结束项目` 或 `放弃项目`：起草结论等你确认 → 释放显卡 → 列出不用的 checkpoint 问你删不删 → 提交 → 归档 → 关入口 |
| 看归档的项目 | 控制台 | 「今天」页和左侧栏最下方的「已归档」，默认折叠；记录都还在 |
| 重新打开 | a100 会话，然后项目会话 | `! ~/bin/rc-start <名字>`，再说 `重新打开项目` |

## 常用命令

都在 a100 会话的输入框里运行。

| 想做什么 | 命令 |
|---|---|
| 开工一张任务卡 | 不用命令：在 App 的项目文件夹里新开对话，说「做 <任务 id>」 |
| 在后台给一张卡开会话（自动派活也用它） | `! board task-start <项目> <任务 id>` |
| 停掉后台开的会话 | `! board task-stop <项目> <任务 id>` |
| 看一个项目的事实包（新会话开场读到的内容） | `! board brief /shared/ssd/dchen/<项目>` |
| 看一个项目的记录问题 | `! board check /shared/ssd/dchen/<项目>` |
| 看哪些常驻入口在运行 | `! ~/bin/rc-start --status` |
| 入口没有自动起来时，手动拉起所有入口 | `! ~/bin/rc-start --all` |
| 重启某个项目的入口（约一分钟后恢复） | `! tmux kill-session -t =rc-<名字>; ~/bin/rc-start <名字>` |
| 看入口的启动记录 | `! tail ~/.local/state/rc/<名字>.log` |
| 看收尾程序和派活程序做了什么 | `! tail ~/gpu-board/state/reconcile.log ~/gpu-board/state/dispatch.log` |
| 重启控制台（一般不需要） | `! tmux kill-session -t =gpuboard; cd ~/gpu-board && tmux new-session -d -s gpuboard '/usr/bin/python3 server.py >> server.log 2>&1'` |
| 看某台服务器上自己的任务 | `! ssh <服务器> tmux ls` |

a100 重启后，控制台和所有项目的常驻入口会自动起来（开机后约一分半钟）。

## 关于会话

- **常驻入口**：断网约 10 分钟会退出，一分钟后自动重启，并尽量接回原来的会话。入口只等你说话，不会自己开始干活。
- **任务会话**：最多同时 4 个；同一个项目同时只有一个会话改代码，它在自己的 worktree（`<项目>/.worktrees/<任务>`）里改，动了核心代码的合并由你决定。
- **换新会话**：会话页上下文标黄时，让它写好交接，再开一个新的。新会话开场会读到事实包（项目规则、已采纳的决定、进行中的任务、在跑的运行、等你的事），不靠记忆。
- **6k04 上的 Agent Safety Atlas**：在 6k04 的 tmux `rc-agent-safety-atlas` 里，自己退出后会自动接回同一段对话；接回时如果问信任家目录，运行 `! ssh xtraa6k04.ddns.comp.nus.edu.sg "tmux send-keys -t '=rc-agent-safety-atlas:' Down Enter"`。

## 打开这个控制台

- Mac 上直接打开 http://localhost:8765/ 。隧道由 Mac 上的 LaunchAgent 维持。
- 隧道不通时，手动开一个：`ssh -N -L 8765:/home/dchen/gpu-board/run/board.sock dchen@xtraa100.ddns.comp.nus.edu.sg`
- 控制台只有你能访问。

## 密钥和 token

放在各台服务器的 `~/.config/secrets/`，一个服务一个文件，只有你能读写。

| 机器 | 有哪些 |
|---|---|
| 6k04 | 全部 10 个（含 OpenReview 账号密码）；原件在 `~/.config/agent-safety/keys.env` |
| a100 | 除 OpenReview 外的 9 个 |
| 6k01、6k03、h100、h200 | 只有 `huggingface.env` |

- 更换某个 token 后，要同时更新：6k04 的原件和拆分出的文件、a100 的对应文件，HuggingFace 的还要更新另外四台。跟研究服务台说一声，它会按同样方式重新分发，不会显示 token 的值。
- 不要把 token 放进 `.bashrc`、共享盘或项目目录；不要在环境里设置 `ANTHROPIC_API_KEY`（会让远程控制失效）。

## 进度记录的格式

各项目 `board/` 目录怎么写，见 `/shared/ssd/dchen/_shared/BOARD_FORMAT.md`。会话改 `board/` 里的文件时，有格式问题会当场提示；项目页「记录维护」里能看到全部。
