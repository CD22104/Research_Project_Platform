# 使用说明

## 在哪里做什么

| 地方 | 用来做什么 |
|---|---|
| 这个控制台（Mac 上 http://localhost:8765/ ） | 看显卡、各项目进度和结果；回复待办、确认结论；给项目改显示的名字（项目页标题旁「改名」）。其他记录都不在这里改 |
| 手机 Claude App 或 claude.ai/code | 和项目会话说话：点项目名（常驻入口）开会话，下达任务、回复待办、确认结论 |
| a100 上的 Claude 会话（例如「A100: 研究服务台」） | 运行下面带 `!` 的命令。`!` 让命令以你的身份直接运行；也可以去掉 `!` 在 a100 的终端里运行 |
| 其他服务器上的 Claude 会话 | 只在需要时用，例如某个任务只能在那台机器上操作 |

## 新建项目

1. **起草**：在 a100 上的任意 Claude 会话里说 `新建项目 <名字>`（名字用英文小写和连字符，例如 `jev-authz`）。
   会话会在共享盘 `/shared/ssd/dchen/<名字>/` 建好目录、`git init`、项目 `CLAUDE.md`、进度笔记和 `board/`，然后列出它替你定的内容。
2. **确认**：在同一个会话里回复你的修改，没提到的视为同意。
3. **起常驻入口**：在 a100 会话的输入框里运行

   ```
   ! ~/bin/rc-start <名字>
   ```

4. **回答信任提问**（每个项目只有第一次）：

   ```
   ! tmux send-keys -t '=rc-<名字>:' y Enter
   ```

5. **开始用**：大约一分钟后，手机 App 或 claude.ai/code 里会出现这个项目名，点它开会话；控制台左侧栏也会出现这个项目。

## 暂停和恢复（暂时搁置，文件不动）

| 想做什么 | 在哪 | 怎么做 |
|---|---|---|
| 暂停项目 | 这个项目的会话 | 说 `暂停项目`。会话确认没有任务在跑后，在进度笔记和 `board/project.json` 里标为「暂停」。控制台把它移到「暂停」一栏 |
| 关掉它的入口（可选） | a100 会话 | `! tmux kill-session -t =rc-<名字>`。入口几乎不占资源，不关也可以 |
| 恢复项目 | a100 会话，然后项目会话 | 入口关掉了的话先 `! ~/bin/rc-start <名字>`；再在项目会话里说 `恢复项目`，状态改回「进行中」 |

## 结束或放弃（归档）

- **在哪做**：在项目会话里说 `结束项目` 或 `放弃项目`。
- **会话会做的事**：
  1. 起草结论，等你确认。
  2. 释放显卡；不用的 checkpoint 列给你决定删不删。
  3. 提交代码，在目录索引里标为已归档。
  4. 最后关掉常驻入口。
- **归档后在控制台哪里看**：
  - 总览页最下方「已归档」，默认折叠，点开就能看到。
  - 左侧栏最下方「已归档」，默认折叠。
  - 项目页和全部记录都保留，和以前一样能打开。
- **重新打开已归档的项目**：先 `! ~/bin/rc-start <名字>`，再在项目会话里说 `重新打开项目`。

## 待办怎么回复

1. **在控制台回复**：待办页（或项目概览的「等你处理」）每条都有背景、选项按钮（标「建议」的是会话推荐的）和补充说明框。选好、写好，点「提交回复」。等你确认结论的尝试也在这里，选 成功 / 部分成功 / 失败 / 放弃。
2. **回复后**：这条显示「已回复 · 等会话处理」。会话处理之前可以点「改回复」。
3. **让会话执行**：在这个项目的会话里说 `处理回复`。会话逐条复述理解、执行，有疑问会问你。不说就不处理。
4. **处理完**：这条移到「最近 7 天办完」，写着你的回复和会话做了什么。

回复存在项目的 `board/answers.jsonl`，只有控制台写它。

## 常用命令

都在 a100 会话的输入框里运行。

| 想做什么 | 命令 |
|---|---|
| a100 重启后，把所有项目的入口都拉起来 | `! ~/bin/rc-start --all` |
| 看哪些入口在运行 | `! ~/bin/rc-start --status` |
| 重启某个项目的入口（约一分钟后恢复） | `! tmux kill-session -t =rc-<名字>; ~/bin/rc-start <名字>` |
| 看入口的启动记录 | `! tail ~/.local/state/rc/<名字>.log` |
| 看控制台自己的日志 | `! tail ~/gpu-board/server.log` |
| 重启控制台（一般不需要，a100 重启后会自动启动） | `! tmux kill-session -t =gpuboard; cd ~/gpu-board && tmux new-session -d -s gpuboard '/usr/bin/python3 server.py >> server.log 2>&1'` |
| 看某台服务器上自己的任务 | `! ssh <服务器> tmux ls` |

## 关于常驻入口

- 断网约 10 分钟入口会退出，脚本会在一分钟后自动重启，并尽量接回原来的会话。
- 入口只等你说话，不会自己开始干活。
- 同一个项目不要同时在两个会话里改文件，会互相覆盖。

## 打开这个控制台

- Mac 上直接打开 http://localhost:8765/ 。隧道由 Mac 上的 LaunchAgent 维持。
- 隧道不通时，手动开一个：`ssh -N -L 8765:/home/dchen/gpu-board/run/board.sock dchen@xtraa100.ddns.comp.nus.edu.sg`
- 控制台只有你能访问；a100 重启后会自动启动。

## 密钥和 token

放在各台服务器的 `~/.config/secrets/`，一个服务一个文件，只有你能读写。

| 机器 | 有哪些 |
|---|---|
| 6k04 | 全部 10 个（含 OpenReview 账号密码）；原件在 `~/.config/agent-safety/keys.env` |
| a100 | 除 OpenReview 外的 9 个 |
| 6k01、6k03、h100、h200 | 只有 `huggingface.env` |

- 更换某个 token 后，要同时更新：6k04 的原件和拆分出的文件、a100 的对应文件，HuggingFace 的还要更新另外四台。跟 a100 的会话说一声，它会按同样方式重新分发，不会显示 token 的值。
- 不要把 token 放进 `.bashrc`、共享盘或项目目录；不要在环境里设置 `ANTHROPIC_API_KEY`（会让远程控制失效）。

## 进度记录的格式

各项目 `board/` 目录怎么写，见 `/shared/ssd/dchen/_shared/BOARD_FORMAT.md`。项目页的「记录检查」会列出写错的地方。
