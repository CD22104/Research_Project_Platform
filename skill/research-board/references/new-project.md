# 新建项目

用户说「新建项目 <名字>」时照这里做。只有能操作服务器的会话才能做；开在别处的会话要转交给服务器上的会话。

## 建什么
在项目根目录建 `<项目根目录>/<名字>/`（名字用英文小写和连字符），然后：

1. `git init`，`.gitignore` 至少包含 `.env`、虚拟环境、`results/`、`ckpt/`。代码要推到远程仓库，共享盘不能当唯一副本；没有远程就告诉用户。
2. **项目 `CLAUDE.md`**：哪些目录算核心代码（研究方法、要发表或长期维护的部分），项目的长期约束（`## 长期约束` 一节，事实包会读它）。
3. **`NOTES.md`**（进度笔记）：只放换会话时的交接和环境说明（怎么装环境、在哪台机器怎么跑、踩过的坑），不记进度。
4. **`pyproject.toml`**：用 `uv` 管理环境，提交 `uv.lock`；虚拟环境建在各台机器本地，不放共享盘，换机后 `uv sync` 重建。PyTorch 选所有服务器的驱动都支持的 CUDA 版本。
5. **`board/` 骨架**，格式照 `board-format.md`：`project.json`（标题、研究问题、状态「进行中」）、`plan.md`、`setup.json`、`method/`、`versions/`、`tracks/`、`attempts/`、`runs/`、`tasks/`、`decisions/`。
   - `setup.json` 建项目时就写好：目标、数据集、模型、指标、方法的定义，以及要解释的术语。每个数据集同时抽 10 条原样样例放进 `board/examples/data/`。
   - `method/` 把方法拆成步骤，一步一个文件：怎么做、输入输出、关键设置。
6. 项目根目录有索引（例如 `README.md` 列出各项目）时，加上这个项目。

## 常驻入口
每个项目在控制台所在的机器上有一个常驻入口：一个 tmux 会话（例如 `rc-<名字>`），在项目目录里以服务模式运行 `claude remote-control --name <名字>`，用户在 Claude App 或手机上点项目名就能开会话。常驻入口只等用户说话，不自己开始项目工作。

- 入口由用户启动（你的环境里可能有一个启动脚本），会话自己不要去启动。
- 第一次启动时 Claude 会问是否信任这个目录，由用户回答。不要替用户回答，也不要改配置绕过。

## 建好之后
列出你替用户定的内容（目录、核心代码的范围、实验设置、方法的步骤），等用户确认再开始写代码。
