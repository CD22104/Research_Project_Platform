# 任务会话：一张卡一个会话

## 三层
- **项目会话**：和用户讨论，维护方案和决定，拆任务卡，看结果；长时间的执行不在里面做。上下文超过约 15 万，或定了新版本，写好交接后换一个新会话。
- **任务会话**：做一张任务卡，从头做到尾，做完写交接。任务会话不再开任务会话。
- **子 agent**：读大量日志或资料时交给子 agent，会话只拿摘要。

## 开工
1. 项目会话把一件具体的事（讨论、执行、写作、分析、审查、调试）写成任务卡 `board/tasks/<id>.md`，格式见 `board-format.md` 的 tasks/ 一节。
2. 请用户在 Claude App 里这个项目的文件夹中新开一个对话，说「做 <任务 id>」。
3. 这个对话开场先运行 `<本 skill 目录>/scripts/board task-begin <任务 id> --session <本会话 id>`（会话 id 在事实包开头）。它检查能不能开工、给改代码的卡建 worktree，然后打印步骤；它拒绝时把原因告诉用户，不要绕过。
4. 自动派活或用户明确要后台开时，才用 `board task-start <项目> <任务 id>`。

## 并行和合并
- 所有项目合计同时最多「任务会话上限」个任务会话（配置的 `max_task_sessions`）。
- 一张卡同时只有一个对话在做；同一个项目同时只有一个会话改代码，且在自己的 worktree 里改。
- 一个项目的多个会话各改各的文件：任务会话只改自己的任务卡、尝试、运行、文档和 worktree 里的代码；共用的文件（`plan.md`、`setup.json`、`method/`、`decisions/`、项目 `CLAUDE.md`）只由项目会话改。
- 收尾时先 rebase 到主线、跑测试。没动核心代码且没有冲突就合并；动了核心代码或有冲突，把卡改成「等你」，在待办里请用户决定合并。

## 做完
写交接：做了什么、证据在哪（文件、运行编号、提交号）、没做完的、下一步、要你决定的。需要用户做或决定的事写进 `board/todos.jsonl`，附上背景、选项和建议。

## 不要
- 不守着：不定时唤醒自己去查进度；需要定时做的事交给脚本（收尾、派活）。
- 同一件事失败 3 次就停下，写进待办问用户。
