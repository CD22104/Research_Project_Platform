# 结束、放弃、暂停、恢复项目

## 结束或放弃（用户在项目会话里说「结束项目」「放弃项目」）
依次做，每一步做完再下一步：

1. **起草结论**：完成还是放弃、结论是什么、放弃的原因。写进 `project.json` 的 `conclusion` 草稿，等用户确认。
2. **确认没有任务在跑**，释放显卡（停掉 tmux 里的训练、关掉起的服务）。
3. **清理 checkpoint**：只保留被结论引用的，其余列出来（路径、大小）问用户是否删除。删除任何大件前都先问。
4. **提交代码**，有远程仓库就推送；没有就告诉用户。
5. **更新项目根目录的索引**，把项目标为已归档；`project.json` 的 `status` 改为「已归档」。
6. 该项目有常驻入口的话，最后关掉它。

放弃的项目同样保留 `board/`，写明试过什么、为什么不行。

## 暂停（用户说「暂停项目」）
不走上面的流程，只做三件事：确认没有任务在跑；在进度笔记里标明暂停（日期、停在哪、恢复时先做什么）；把 `board/project.json` 的 `status` 改为「暂停」。其他文件不动。

## 恢复（用户说「恢复项目」「重新打开项目」）
把 `status` 改回「进行中」，在进度笔记里记一笔；常驻入口没在运行的话，提醒用户启动它。
